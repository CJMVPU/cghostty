# 完整终端帧时钟实验：预先约定的范围与口径

基线：ad85cd1a9。正式构建仍只有 CAMetalDisplayLink；实验编译条件不进入普通 Release/ReleaseLocal。
外接显示器、高速摄像、能耗测试由用户明确排除，不阻塞本轮，也不记录为通过。

## 步骤

1. 补窗口回调、状态转换、drawable 获取和连续呈现指标；运行正常启动、激活的完整终端基线。
2. 同一源码与 ReleaseFast/ReleaseLocal 优化，编译 metal/view 两个实验构建。
   相同 3 drawable、当前屏幕最高请求帧率、相同渲染与数据结构，按 A/B/A/B 顺序采样。
   每个场景在 PTY 就绪后预热 1 秒并确认时钟暂停；连续输入/滚轮/nvim 以 16ms 输入间隔驱动。
   空闲后输入每次等待该窗口回到暂停状态，静止观察持续 2 秒。
3. 每轮输入场景初筛 200 个探针，保留无效/未匹配/丢弃记录；关键候选再扩大样本。
   场景：静止观察、空闲后输入、连续输入、四分屏一窗大量输出而另一窗输入、
   冷中文字、终端历史滚动、真实 nvim classic/instant 光标及文件区域滚动。
4. 在明确存在收益后，以 view 基线分别测试晚取 drawable 和呈现时间经验校正，避免归因混淆。

## 验收口径

- 先看输入探针到对应内容呈现的中位数是否减少至少一个本机刷新周期（120Hz 为 8.33ms）。
- p99 不因时钟替换而持续退化：200 样本只作初筛，尾部结论需要扩样本和重复轮次。
  在扩样本前不凭最慢的两三个点宣布 p99 已通过。1ms 内差异视作待确认的测量波动，不能冒充改善。
- 四分屏持续输出的长呈现间隔比例不能稳定上升；按窗口与连续活动区间计算。
  超过 1.5 倍请求周期称为“长间隔”，不直接等同 GPU 丢帧；零呈现时间另计。
- drawable 获取 p99 以小于 0.25 个周期作为初筛目标，前台稳定区间 nil 次数要求为零。
- 静止区间要求窗口帧时钟保持暂停，无持续回调；这只验证窗口调度，不等价进程零唤醒或功耗通过。
- 预测误差为实际呈现减预测，记录有符号分布；校正以同一帧 targetTimestamp 的残差为基准。
- `window_prepare` 保持原口径（各分屏更新和编码），不误称为纯 CPU cell 准备。
- 输入探针是 native Surface 输入入口到经过 PTY 回显确认的内容呈现，不是物理键盘到发光。
- 前台失活、未完成场景、资源失败的轮次保留诊断但排除比较。trace 不完整时明确报告可匹配率。

仅根据可完成的这些软件指标给出采用建议；缺少能耗、跨屏和光学验证时，不声称完成所有硬件验收。
