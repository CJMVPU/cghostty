# GPU 资源、搜索快照及原生刷新优化验证（2026-09-24）

基线：`4254a674b`。版本保持 0.2.7（build 17）。目标为 macOS 27+、Apple Silicon；核心使用项目固定的 Zig 0.16.0，原生回归使用 ReleaseLocal。

## 实现与边界

1. **GPU 资源失败恢复**：字体纹理先完成新资源的分配与上传，再释放旧纹理；只有成功后才更新帧槽的图集版本。Shader 同样先构建替代资源，成功后替换并清除重建标记。失败会退出本次绘制并保留重试条件。
2. **字体图集增量上传**：图集保留最近 256 次写入区域，帧槽按自身版本合并尚未上传的区域。记录不被单个消费者清空；首次同步、扩容、清空及历史过期均覆盖整个图集。区域上传使用源图集的行跨度，兼容灰度和 BGRA 字形。变更记录读写受原有字体网格锁保护。
3. **渲染工作区复用**：帧临时 arena 在帧结束后重置，最多保留 256 KiB；链接文本工作区超出 256 KiB 后释放。链接正则匹配器最多缓存 16 个，其余按需临时创建；配置切换时先释放旧匹配器，再释放旧正则。现有正则执行预算不变，未放宽输入限制。
4. **搜索视口共享快照**：匹配结果直接收集到拥有独立内存的不可变快照，搜索缓存和渲染消息通过原子引用计数共享，不再二次深复制。页面指针仍只用于携带序号的身份判断，不增加无锁解引用。空结果不分配内存；选中项和查询导航保持原有顺序。本轮没有合并消息或修改导航语义。
5. **标题栏刷新**：标题与字体变化合并到下一次主线程刷新，一次查找标题字段；只在字段身份变化时重新登记观察器。弱引用避免持有被 AppKit 移除的视图。透明标题栏根据标签组、附属视图及几何变化请求刷新，去掉 50 ms 补刷等待，并合并观察器重绑定请求。
6. **原生回调整理**：保留中央动作分发，将剪贴板、窗口与展示状态处理分别移入扩展文件；按键序列在入口转换成 Swift 数据，由展示层延迟执行一次，去掉两层主线程排队。

## 验证方法

核心定向回归包含图集、搜索全模块、SearchSession、RenderSession、链接缓存和同步输出：

```sh
python3 scripts/build.py test \
  -Dtest-filter='atlas upload' -Dtest-filter=font.Atlas \
  -Dtest-filter=search -Dtest-filter=SearchSession -Dtest-filter=RenderSession \
  -Dtest-filter='link cache' -Dtest-filter=renderCellMap \
  -Dtest-filter='render hold' -Dtest-filter='GUI synchronized' --summary all
nu macos/build.nu --configuration ReleaseLocal --action test
python3 scripts/check-scope.py
python3 scripts/check-versions.py
python3 scripts/check-localizations.py
python3 scripts/check-swift6.py
```

字体上传的核心测试通过内存纹理替身检查源行跨度、三个帧槽交替同步后的全部像素、清空、历史过期和扩容分配失败后的重试。资源分配失败是替身注入，不代表已在真实 Metal 设备上诱发内存耗尽。Shader 失败处理由代码路径检查与原生编译验证，未单独注入 Metal pipeline 创建失败。

搜索测试包含逐点分配失败清理、生产者释放后快照仍可读取，以及多个消费者共享同一份高亮内存。原生回归包含现有真实 PTY 搜索和 Kitty 图像像素测试，以及新增标题字段观察器复用、弱引用释放、透明／标签标题栏在两标签变一标签后的外观。

## 工作量计数

测试日志中的 `RESOURCE_METRIC` 输出为确定性工作量，不是端到端耗时或 CPU/GPU 占用率：

- 图集负载：16×16 图集，12 次 2×2 区域写入，三个帧槽轮流消费。初始化的全量上传不计入比较；比较每次同步整张图集与实际合并区域的上传字节数。灰度与 BGRA 分别验证，像素结果必须完全一致。
- 链接负载：80×4 视口，101 次等长文本更新；第一轮预热后检查 Zig 分配器调用次数，以及文本缓冲区和 PCRE2 匹配工作区地址是否复用。PCRE2 内部 C 堆分配不在 Zig 分配器计数范围内。
- 搜索负载：1,000 个带高亮块的匹配，一份快照被 100 个消费者依次保留和释放。计数只覆盖共享阶段，初次采集和复制仍需要分配。

最终测量：

| 工作负载 | 结果 |
| --- | --- |
| 灰度图集，12 次更新 | 全量策略 3,072 字节；增量策略 237 字节 |
| BGRA 图集，12 次更新 | 全量策略 12,288 字节；增量策略 948 字节 |
| 链接预热后 100 次内容更新 | 0 次额外 Zig 分配；文本缓冲区及匹配数据地址保持不变 |
| 搜索快照 100 次共享 | 0 次额外分配；所有消费者指向同一份 1,000 项匹配结果 |
| 标题字段同一视图更新 100 次 | 只登记 1 次观察器；替换字段后只登记新增字段 |

更大或相距很远的字形写入区域可能合并成接近完整图集；历史过期也会回退全量上传。因此这些计数不能直接推广为日常终端速度或功耗改善比例。
