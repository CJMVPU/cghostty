# 渲染路径统一与精简验证（2026-09-28）

本轮按用户决定保留现有呈现延迟，统一到 CAMetalDisplayLink，精简动画与绘制路径。基于 `a83f5e7ff` 及前一轮未提交的 GPU 时间线诊断改动完成。历史时钟对照数据保留作档案，不代表当前仍支持那些变体。

## 实现范围

- 窗口只保留 CAMetalDisplayLink，直接使用回调提供的 drawable 和预计呈现时刻。删除 NSView 时钟、晚取 drawable、呈现时间估算/校正及其跨语言准备接口。呈现反馈仍用于诊断，不再影响动画取样。scope 检查拒绝这些旧路径重新引入。
- `cursor-effect-mode` 只接受 `responsive`（默认）和 `instant`，移除 `classic` 及专属时长状态。沿用已有名称 `responsive`，没有新增 `response` 别名。配置模板和说明同步更新。用户配置本来已选 responsive，只更新过时注释，并先创建备份。
- 静止光标只提交光标行的文字和前后两个光标槽位，保持反色、组合字符、宽字符及绘制顺序；动画光标沿用保守边界裁剪。光标主体、拖尾、形变在预计呈现时刻全部结束后，停止额外帧请求，保留真实时间下的运动状态供下次输入使用。
- 重复、未改变的布局不唤醒窗口时钟；屏幕和 backing 变化可以显式要求重新合成。
- 图集最多保留 8 个上传区域。只有合并后的像素面积不大于分开上传才合并；碎片超过上限时收敛为一个外接区域。首用、扩容和历史过期仍完整上传；每个帧槽独立记录版本，任何区域上传失败都不推进版本。
- 帧槽部分初始化失败时回收已创建资源。GPU 完成回调把健康状态合并到原子状态并唤醒 app tick，不再等待有界消息队列空位。编码器创建失败时中止未提交的命令缓冲、释放资源、失效场景缓存，不记录成功的光标历史。
- 移除已禁用的全屏实现、监听器、原生配置快照字段和 UI 分支。保留旧恢复档案的枚举解码，以及固定尺寸约束、跨屏和 backing 更新。

没有改动每窗口合成器和 Metal 4 队列架构。图集继续按帧槽管理资源，本次减少的是无效上传区域；没有引入共享 GPU 图集、后台汉字预热或并行准备线程。

## Metal 验证层发现及修复

首轮四项光标 UI 测试在启动时失败，Metal 报告 `texture view creation not allowed from frameBufferOnly textures.`。窗口 drawable 原来设为 `framebufferOnly = true`，但合成器为了不同混合模式创建 linear/sRGB 纹理视图，两者不相容。改为 `false` 后，原四项测试在相同 Metal 验证层下全部通过；仍使用原 drawable 和窗口合成器。

这项修复来自验证层的实际断言，不是帧时钟替换。首次失败和通过后的结构化摘要均保留在[测试记录](2026-09-28-renderer-unification-tests.json)。

## 验证结果

- 渲染器、配置和图集核心测试：383/383 通过。
- 原生全套：362 通过、1 跳过、0 失败，共 363 项。跳过项为已有的 `Benchmarks/example` 占位测试。
- 真实窗口光标像素测试：4/4 通过，开启 Metal 验证层，约 248 秒。覆盖文字缓存/闪烁、有留白和零留白移动、长距离转向、宽字符及光标形状切换。
- Python：47 通过、4 个可选依赖测试跳过，共 51 项。
- SwiftLint、Zig 格式、scope/配置桥接、版本一致性、独立 CAMetal 探针编译检查及 diff 空白检查通过。

没有注入真实 GPU 设备丢失。资源初始化与编码失败路径进行了代码检查；图集替换失败、区域上传中途失败和重试有确定性回归测试。

## 前台完整终端负载

仅 CAMetalDisplayLink，3 个 drawable，系统默认帧率策略，内置 ProMotion 120Hz，独立配置和真实 PTY/nvim。测量时没有并行构建。实验窗口未包含普通窗口控制器的全部装饰；普通窗口另由原生和 UI 套件覆盖。九个场景全部完成，每阶段渲染失败均为 0。三个输入场景各发送并匹配 200 个输入探针，合计 600 个。

单元测试中，40×80 格的静止光标只需 80 个文字实例加两个光标槽位，原全量参考为 3,202；两个相距很远的单像素灰度图集变动只上传 2 字节。前台中文冷字形场景图集仍上传约 100.2 MB，不能声称本次消除了帧槽副本或首次字形光栅化开销。

连续输入和四分屏场景，提交到 `presentedTime` 的中位数分别为 40.70ms、40.48ms，仍在此前约 41ms 的区间。本轮没有降低呈现延迟的验收目标。`presentedTime` 不是物理发光时间；未测外接屏、高速摄像或能耗。

全过程丢弃 61 条 trace 记录。600 个输入探针都匹配成功，但完整时间线统计仍存在缺失和零呈现样本，不能当成无缺口的基准测量。原始数据见[压缩 trace](2026-09-28-renderer-unification-raw.json.gz)，指标见[完整统计](2026-09-28-renderer-unification.json)。本轮为一次本机回归观察，不是跨机器性能承诺。

前台和像素测试之后的收尾，仅删除了 classic 已无读者的基准时长字段，并将恒定时长函数改为常量。最终源代码再次通过 383 项核心测试及原生全套；没有重跑整轮前台采样。最终原生结果包显式保存在 `/private/tmp/cghostty-unify-final.xcresult`。
