# Settings refactor validation

## Scope

Six changes following the settings audit:

1. Bound settings lock waits to two seconds. Async waits yield and propagate
   cancellation before a transaction starts. Atomic rename remains the commit
   point; cancellation after committing cannot report a failed save.
2. Wait for a successful saved status before UI tests close or restart the app.
   Share opening/activation helpers and handle transient input-source indicators.
3. Share save preparation, validation, revision checks and disk commits between
   synchronous startup/test callers and the async editor. Model save tests use
   the same async entry point as the UI.
4. Represent operation and validation states explicitly. Derive status messages
   and button availability, preserve drafts on failure, and coalesce initial loads.
5. Keep original Xcode results separate from current verification and a bounded
   history. Successful revalidation clears the current failure marker.
6. Reuse rows, section headings and separators by stable keys. Reconcile only
   changed views, preserve surviving editors, and clear row caches on reload.

Settings remain restart-based. This release does not introduce hot reload.

An intermediate run passed three scenarios but was interrupted by the macOS
input-source indicator during the close/save scenario. After sharing the
interruption handler, a second run exposed a focus timing issue with keyboard
reopening after closing the modal window. Opening through the app menu after
foreground activation passed the targeted retry. No fixed delay was added.
