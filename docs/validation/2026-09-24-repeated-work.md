# 第二批六项优化验证（2026-09-24）

基线提交：`c140e5706`。以下构建、测试及测量使用 0.2.5（build 15）元数据；随后提交时同步升版为 0.2.6（build 16），未重新构建发行包。环境：Apple M5 Pro、macOS 27.0（26A428）、Zig 0.16.0；原生测试使用 ReleaseLocal，核心性能对照使用 ReleaseFast。

## 实现

1. **命令面板**：选项生成时计算排序标题，比较器不再重复替换字符串。命令和终端条目使用稳定身份；搜索结果、排序和文字高亮索引按查询及候选内容缓存。缓存命中仍更新选项，避免保留过期回调或显示信息。缓存键按 UTF-8 字节比较文字，避免规范等价但编码不同的 Unicode 字符串复用错误索引。
2. **分屏树**：移除每次下标访问重新展开叶节点的 Collection 实现，改为从左到右的惰性深度优先 Sequence。只有确实需要随机访问时才显式生成数组。WindowRegistry 通过对象身份集合判断被移除的窗口成员，保留原有归属检查。
3. **拖拽预览**：直接生成目标像素尺寸的位图，并保留屏幕缩放比例；不再先创建整个终端尺寸的位图再缩小。与 PNG 缩略图共用位图生成入口，删除旧的全尺寸 asImage 入口。
4. **链接匹配**：渲染器保留一个视口的文字到终端格映射及正则匹配范围。内容、布局、配置、修饰键等输入不变时，鼠标移动只选择已有范围。匹配预算和原有高亮语义保持一致；缓存不持有终端页指针，构建失败不会发布部分结果。
5. **搜索消息**：同一轮邮箱处理中的连续查询只应用最后一个，并释放被覆盖的查询。前后匹配导航作为顺序边界，先应用此前查询，再执行导航；没有增加固定时间等待。
6. **无障碍快照**：通过独立于渲染器脏标志的修改编号、屏幕身份、范围端点、选区及尺寸，判断上次快照是否仍有效。未变化时，C 桥接不重新采集或分配文本；Swift 同时复用不可变快照和 UTF-16 行索引。现有 500 ms 懒刷新节奏保持不变。

编号是保守失效机制：部分无实际内容变化的操作也会触发重建，优先保证文本和范围正确。未来增加直接写入终端格或改变文本布局的路径时，须同步维护修改编号。持续输出、选区或视口变化时仍可能重新采集完整快照；本轮没有实现按页增量拼接历史文本。

## 验证结果

- 核心定向测试：**79/79 通过**，72/72 构建步骤成功。涵盖无障碍文本/范围、渲染器消耗脏标志后的失效检测、主辅屏切换、覆盖/擦除/滚动/缩放、缓存与旧链接算法结果一致、搜索合并及导航顺序。
- 原生测试：**44 个套件、336 项测试，335 通过、1 跳过、0 失败**。包括命令排序一致、缓存失效及回调刷新、分屏顺序与迭代器独立性、目标位图尺寸、真实终端桥接快照版本及生命周期。跳过项为既有 Benchmarks 示例。
- Python 构建维护测试：**24/24 通过**。
- macOS arm64 范围、C 配置桥接、版本一致性、本地化、Swift 6 配置、变更 Swift 文件严格 lint、Zig 格式和差异检查通过。
- ReleaseLocal 原生测试应用和 ReleaseFast 核心基准构建成功。

测试过程中发现并修正了旧 Collection 调用者适配，以及新增 Zig 测试将字符串字面量作为固定数组传给消息接口的问题。最终结果以上述通过的定向及原生回归为准，不把之前失败的中间运行计为通过。

本地结果包：`/private/tmp/cghostty-round2-native4.xcresult`。核心日志：`/private/tmp/cghostty-round2-core4.log`。没有运行完整核心测试套件、桌面 UI 自动化或人工 VoiceOver 连续朗读/Metal 终端拖拽验收。

## 局部性能对照

### 命令排序

170 条含中文的候选，每轮排序 50 次，五轮对照；每轮检查新旧排序相同。旧方法每次比较替换标题字符串，新方法使用预计算标题。五轮总耗时中位数：**154.609416 ms → 38.897708 ms**，约降低 74.8%。这仅计排序，不是整个命令面板打开时间。

### 分屏遍历

128 叶节点的不平衡树，连续取首个元素 1,000 次：旧递归数组展开 **36.045708 ms**，新迭代器 **0.661584 ms**。这是突出短路访问收益的单轮微基准，不代表所有分屏操作。

### 拖拽位图

同一个 1600×800 点的 AppKit 测试视图，以相同 Retina 密度生成 320×160 点预览，共 20 次：旧路径 **384.037250 ms**，直接位图路径 **1.031833 ms**。旧全尺寸中间位图为 3200×1600 像素、**20,480,000 字节**；目标位图为 640×320 像素、**819,200 字节**，该位图分配减少 **96%**。

这是简单填色 AppKit 视图的单轮测量；字节数只统计对应位图，不代表进程峰值内存，也不等同于真实 Metal 终端的端到端拖拽延迟。

### 无障碍和链接缓存

输入先生成到固定文件，之后全部模式复用同一文件。输入为 10,000 行含 URL、中文、emoji 的文本，680,000 字节；终端为 120×24，显式配置 64 MiB 历史容量，避免默认容量裁剪输入。采集后的文本为 670,142 字节。解析输入和准备视口在计时前完成；一个预热轮次后顺序运行五轮，没有并行运行基准。

## 复现

将项目固定的 Zig 0.16.0 和 Nushell 放入 PATH 后：

```sh
python3 scripts/build.py test -Dtest-filter='search mailbox' -Dtest-filter=accessibility -Dtest-filter=renderer.link --summary all
nu macos/build.nu --configuration ReleaseLocal --action test
python3 -m unittest discover -s scripts/tests -v
python3 scripts/build.py core -Demit-bench -Doptimize=ReleaseFast -Dversion-string=0.2.5
```

先独立生成输入：

```python
from pathlib import Path
Path('/private/tmp/cghostty-round2-corpus.txt').write_bytes(''.join(
    f'{i:05d} https://example.com/path/{i:05d} 中文🙂 snapshot benchmark\r\n'
    for i in range(10000)
).encode())
```

以下顺序执行六轮，第一轮预热，剩余五轮计算中位数；耗时使用工具打印的 `elapsed_ns`：

```sh
for mode in accessibility accessibility-reuse links links-cached; do
  zig-out/bin/ghostty-bench +screen-clone --mode="$mode" \
    --data=/private/tmp/cghostty-round2-corpus.txt \
    --terminal-cols=120 --terminal-rows=24 --scrollback-bytes=67108864
done
```

原生微基准位于 `CommandPaletteReuseTests`、`SplitTreeTraversalMeasurementTests`、`ThumbnailTests`；随原生测试运行。本记录随优化代码和 0.2.6 版本信息一起提交；没有打标签、发布或替换已安装应用。
