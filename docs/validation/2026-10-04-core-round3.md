### PTY 总待写字节和控制公平性

现有链路是 native borrowed text → 64-slot mailbox/send.forever → drain → Exec/libxev FIFO。限制 mailbox 个数不限制 owned 字节；在高水位停止 pop 会挡住控制消息，甚至使主线程 forever 发送阻塞；把数据移进另一条无界队列也不构成背压。

建议单独设计 native pending、mailbox owner 和 in-flight libxev 的总预算与异步 credit/cancellable source。一次逻辑 bracketed frame 可以分段写，必须完整结束才允许下个输入或协议回复插入；linefeed mode barrier 和 control/stop 路径保持独立。无限生产者、无损、非阻塞和固定 RAM 无法同时满足，需要明确 streaming/retry/spool 的产品策略。close 时先停 admission、取消 pending，再 stop/join 并逐一释放。

可复现后续基准：真实 Thread callback + raw PTY，固定 seed/SHA 的 1/8/32 MiB 和 32×1 MiB burst；fast、每 4 KiB 暂停 1 ms、暂停 500 ms 三类消费者。串行 3 warmup/15 repeats，报告 enqueue return、resize request→真实 winsize ack（25 ms coalesce 配 idle baseline）、stop notify→loop join 的 p50/p95/max；同时记录 native/mailbox/in-flight 峰值字节、字节 SHA/FIFO 和 release 数量。本轮没有实施或测量这个基准，旧 loop tick 不能替代控制消息延迟。收益可能高，状态机/退出语义风险高，预计 3–5 天含压力验证。

### Reflow 的局部重复及冷页策略

已有 capacity/style cache/bulk copy/source pool/compression scratch，不能重复建议重做。`src/terminal/PageList.zig:2242/2259` → `src/terminal/Page.zig:1496` 可能先预分配/free grapheme 再分配；这里是 page 内部 chunk，不等于两次系统 heap 分配。可测直接尝试一次后按容量错误增长并重新解析 cell 指针，覆盖 map/cluster/OOM。OSC 8 按 cell dupe/lookup/free 可探索以 source page/link→destination ID 的映射缓存，页面增长及跨页时重置并维持 refcount；此前 reflow corpus 没有 OSC 8，不能用旧数据声称收益。收益待测，风险中等，各约 1–2 天。

moveLastRow 中为了比较节点而取 p.node.page() 会提前恢复无关冷页，节点身份比较可避免局部提前解码；整个列宽 resize 最终仍恢复所有页，不能声称减少完整 reflow 解码数。此前 200 MB cold 循环 p50 62.137 ms 是已有测量；lazy reflow 需先设计 width generation 与 pin/selection/search 一致性，本轮未实现。

### Kitty 图像预算

`src/terminal/kitty/graphics_storage.zig:984` 的 convertImageToRgba 会由 RGB 扩为 RGBA 并增加 total_bytes，graphics_exec 的根 edit/compose 路径可能缺少扩容前预算预留。先建立真实 1×1 RGB、预算 3 字节→RGBA 4 字节负回归，逐一验证 root/frame/compose 和 eviction；设计事务预留及 eviction 后重新解析指针，避免悬空 image。当前只是具体静态候选，未复现/修复，也没有测量收益；风险中高，约 1–2 天。
