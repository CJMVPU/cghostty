## GPU 改动

上一轮已实现前景行增量上传。本轮在每个可用帧槽的行元数据中缓存实际
字形四边形的包围区域，仅在行版本或字符尺寸变化时重新计算。

动画方块光标的文字覆盖层选取与主体及拖尾相交的候选行，合并成一个
连续实例区间；绑定原缓冲区的字节偏移，不创建第二份文字缓冲区。
Metal scissor 再限制光栅化范围，绘制后恢复完整附件范围，防止影响后续步骤。
范围考虑字形伸出单元格、组合字符、padding 和滚动偏移；多滚动区域采用
保守候选范围，允许多提交，不裁掉应显示的字形。

动画竖线和下划线不需要重着色文字，直接省去文字覆盖层。原生光标保留
原有完整绘制路径。光标主体 shader 本来已按主体/拖尾边界绘制，本轮主要
缩小的是额外的文字覆盖层，而不是把整个窗口改成局部重绘。

固定 40 行、每行 80 个文字实例的测试，覆盖层从 3,202 个候选实例降为
80 个提交实例，减少约 97.5%；这是提交工作量，不是整机性能提升比例。
新增 trace 事件记录全量候选数、实际提交数和裁剪像素面积；旧 trace 缺少
这些字段时汇总为 null，避免把未知误认为零。

CPU 端 `draw_total_ms` 也有波动，例如分屏为 0.2841 → 0.2483 / 0.3452，
不能据此宣称所有场景 CPU 或整体帧时间都改善。

基线 Kitty 阶段丢失 1 条 trace，第 1 轮输入阶段丢失 1 条，第 2 轮长跳、
分屏阶段分别丢失 4、7 条；相关样本不完整。只有一轮基线、两轮修改后观测，

且真实 UI 回归保持正确；表中的短时耗时变化应结合这些限制解读。
