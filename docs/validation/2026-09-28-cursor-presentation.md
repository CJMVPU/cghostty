# 光标呈现时轴与 0.4.2 验证（2026-09-28）

基于 0.4.1 / `8fe6bb413`，合并同工作区已验证的离散滚动修复，版本更新到 0.4.2 / build 32。

## 问题与设计

旧 CursorMotion 用当前回调时间更新 SmoothCursor，再单独按预计显示时刻取样。
光标最短移动只需 24ms；当预计显示时刻比当前时间晚约 40ms，首个样本已经到达目标。
这是动画取样行为，不等于 GPU 需要 40ms，也不是人为增加了 40ms 等待。

新增的短距离回归在旧实现上失败：首帧已走完整个单元格，下一帧不存在中间位置。
修复后只传入一个预计显示时刻，目标、位置、形状、拖尾和结束状态共用这一时轴。
不再二次向未来取样，移除 sampleAt 双时间参数接口及未使用的 FrameTiming.update 字段。
已提交的历史时间用于防止预测回退导致倒放，不依赖 presentedTime，也没有添加时间估算器。

保留 responsive 原有的距离时长、连续输入加速、同向速度衔接、反向限制和形变；
instant 仍立即到位。短 responsive 动画在首次画面出现后继续完成，因此与旧版首帧
直接到位相比，主体最终到位会更晚。这是保留可见动画的取舍，不是呈现延迟优化。
没有改变 CAMetalDisplayLink、刷新率策略、窗口合成或缓冲数量。

## 验证

- 修复前：短距离呈现提前量回归失败（`/private/tmp/cghostty-cursor-before.log`）。
- 最终核心：187/187 通过，覆盖 renderer 和 ScrollState。
- 对 0、16、41.5、83ms 的时间差，在 60/120Hz 下检查连续输入轨迹与形变一致，
  并覆盖相同目标、中文宽度变化、回退预测、停止后休眠及 instant 切换。
- 0.4.2 / build 32 ReleaseLocal 光标图形回归：4/4 通过，0 跳过，启用 Metal 验证层。
  覆盖文字反色与闪烁、主体和拖尾、零留白、宽字符及形状切换。
- 同一构建的 WindowCompositorTests：10 个测试方法、23 个展开用例通过，0 跳过。
  覆盖最终合成动画、缓存、分屏移动、窗口关闭及空闲调度。
- Zig 格式、diff 空白、版本/标签命名一致性、测试应用包版本、Xcode 项目格式、
  范围和配置桥接检查通过。
- 结构化结果见[测试摘要](2026-09-28-cursor-presentation-tests.json)。

41.5ms 仅是覆盖当前观测量级的测试输入，生产逻辑没有这一常量，也不会据此等待。
预计显示时刻相对回调的提前量，与提交到实际呈现的耗时是不同指标。
本次未重跑整套前台延迟基准，不声称降低输入到呈现延迟或功耗。
